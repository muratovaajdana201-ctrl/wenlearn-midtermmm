Quiz - Week 10: Asynchronous JavaScript

11 questions: 8 on theory and 3 on code. Choose your answers, then press Check Answers.

1. What is the difference between synchronous and asynchronous code?

Correct answer: Synchronous statements run one after another, while asynchronous operations can finish later and other code continues meanwhile. In synchronous code each statement must finish before the next one starts. Timers and network requests are asynchronous: they complete later and do not block the rest of the code.

2. Which part of the JavaScript runtime keeps track of the functions that are currently executing?

Correct answer: The Call Stack. The Call Stack tracks the functions being executed. Web APIs handle timers, fetch requests and events, and the Event Loop schedules the queued work.

3. What does the Event Loop do?

Correct answer: Moves queued callbacks to the call stack when the stack is free. The Event Loop checks the queues and, when the call stack is available, schedules the next callback for execution.

4. Which callbacks are microtasks?

Correct answer: Promise handlers: .then(), .catch() and .finally(). Promise handlers are microtasks. Timer callbacks are tasks (macrotasks). After the current synchronous code finishes, microtasks run before the next task.

5. What is Callback Hell?

Correct answer: Deeply nested asynchronous callbacks that make the code hard to read and maintain. Callback Hell appears when callbacks are nested inside callbacks. Promises and async/await are used to avoid it.

6. What are the three states of a Promise?

Correct answer: pending, fulfilled, rejected. A Promise is pending while it is not settled, fulfilled when it succeeds and rejected when it fails.

7. What does the async keyword do?

Correct answer: Makes a function always return a Promise and allows await inside it. An async function always returns a Promise, and await pauses that function until a Promise settles without blocking the whole thread.

8. Why should you check response.ok after fetch()?

Correct answer: Because fetch() does not reject for HTTP errors such as 404. fetch() rejects only when the network request fails. For a 404 or 500 response the Promise is still fulfilled, so you must check response.ok yourself.

9. What is the output order? 
console.log("Start");
setTimeout(() => console.log("Timer"), 0);
console.log("End");

Correct answer: Start, End, Timer. The synchronous lines run first. The setTimeout() callback is a task and runs later, even with a delay of 0.

10. What is the output order? 
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");

Correct answer: A, D, C, B. A and D are synchronous. The Promise handler C is a microtask and runs before the timer callback B, which is a task.

11. What does this code do? 
async function load() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/users");
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error(error);
  }
}
load();

Correct answer: Requests the data, waits for the response, parses the JSON and logs it; errors go to catch. await pauses load() until fetch() and response.json() finish. If anything fails, the catch block handles the error.
